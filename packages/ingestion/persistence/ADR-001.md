# ADR 001 — identidad estable y selección explícita (antes de implementación)

La identidad lógica depende de tenant + connection + entity + external_id; la revisión opaca nunca ordena versiones ni forma parte del ID lógico. source_revisions conserva un snapshot canónico inmutable (valores y relaciones), hash/raw ref y un ID de revisión distinto. Mensajes además usan message_revisions existente.

source_heads serializa por identidad mediante UNIQUE + bloqueo transaccional. Primera versión es única; una segunda versión distinta invalida la selección: estado ambiguous, selected_revision_id null, importación en cuarentena y valores monetarios de orden/línea null. No se elige por fecha local, alfabeto ni importe. Todas las versiones siguen recuperables. La proyección es una sola fila lógica; las relaciones originales están en snapshots.

Una selección explícita requiere scope import, owner vigente comprobado en DB, razón, revision_id y expected_version CAS. Aplica el snapshot seleccionado y añade auditoría inmutable con actor derivado de sesión SQL. Cada nueva revisión invalida otra vez la selección. Lectura programática entrega cabeza e historial; UI05 consumirá estas APIs.

CSV resuelve referencias externas/SKU dentro del tenant y conexión, rechaza ambigüedad o inconsistencias, y nunca crea una orden desde amount. Container de conversación estable entre revisiones, con contexto de relaciones validado. Nulos legítimos no reciben fechas ni roles inventados. No se alteran raw/hash/owner/scopes ni contadores previos.

SQL006 cambia antes de freeze; tablas/FKs/nulabilidad se documentarán para ampliar la matriz externa, sin modificar su examen. No hay aceptación implícita.
