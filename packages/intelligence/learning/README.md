# Histórico autorizado → desarrollo y feedback

Ruta `/evaluation`, API privada `/api/evaluation`. Sólo owner activo; tenant de la sesión y selector de organización, nunca del body. No añade configuración de proveedor, inferencia ni gasto. Depende del lector de evidencia/redacción existentes y SQL0033; SQL0036 añade sólo el workspace de evaluación. El enlace «Evaluación histórica» aparece en Gestión.

El owner elige conexión, taxonomía exacta, inicio de disponibilidad y corte exclusivo. La versión de taxonomía es el hash de su array persistido, no una versión humana inventada. Se congela la última extracción succeeded/abstained de cada conversación para esa taxonomía, con `updated_at` dentro de la ventana. Máximo500; superar el límite produce413, no truncamiento. Cohortes y casos se recorren en páginas de25 con cursor autorizado. El mismo requestId y parámetros reproduce la cohorte; reutilizarlo con otros parámetros produce409.

Sólo se guardan IDs, hashes, taxonomía y feedback estructurado. No hay columnas de comentarios, mensajes o citas en el nuevo ledger. Cada lectura reutiliza `createEvidenceRepository`, valida hashes/revisiones/procedencia y verifica tombstones, conexión y owner vigentes. El corte exige `event_time` y `available_at` anteriores, incluidas disponibilidad de revisión original/redactada, extracción y vínculo canónico. Fuente retirada o resultado cambiado se excluyen con razón; un error SQL/IO falla la petición y no se interpreta como ausencia.

El feedback requiere confirmación explícita, versión CAS, huellas de resultado/manifiesto/taxonomía y etiquetas de esa taxonomía. Sus versiones son append-only. El botón de evidencia abre el lector autorizado existente. La tabla de feedback no contiene una copia del resultado ni de sus citas. Borrar la fuente impide posteriores lecturas/exportaciones y mantiene sólo referencias/hashes/valoraciones autorizadas. Una descarga ya entregada fuera del sistema no se puede retirar técnicamente.

La descarga es un bundle JSON con `dataset`, `spec`, `protocol`, `development`, `provenance`, `excluded` y conteos exactos. Usa directamente `freezeProtocol`/`exportDevelopment` del evaluador existente. Dataset siempre `silver_assisted`, todos los casos `dev`; el feedback autenticado es `kind:human, blind:false`, no gold independiente. Un caso exige cliente canónico actual de la misma conexión; si falta, se excluye como `customer_unknown` o `customer_binding_unavailable`. Cliente, grupo/conversación, revisión y anotador se pseudonimizan desde identidades reales; no se inventan clientes para cumplir el esquema. Todos permanecen en desarrollo; no se recibe, genera ni expone holdout.

Los mensajes se reconstruyen al exportar desde las revisiones redactadas que valida el lector, nunca desde texto RAW o mapas PII. La política de redacción configurada conserva su alcance: diccionario de nombres no equivale a NER universal. No se certifica anonimización de datos reales por haber probado canarios sintéticos. El bundle contiene hashes por ejecución y versión de feedback para auditar procedencia. Presupuesto:500 casos,25 por página,2MB acumulados de mensajes serializados,16KiB por petición; las respuestas incluyen además metadatos/acuses. El export es una lectura acotada y no una nueva inferencia.

Compatibilidad CLI: separar `dataset` y `spec` del bundle en archivos privados; ejecutar los comandos `freeze` y `export-dev` documentados en `../evaluation/README.md`. Las pruebas del autor lo hacen con datos derivados de Auth/PG reales y comparan casos byte por byte; no modifican el CLI. El protocolo de la descarga tiene su instante de freeze; uno generado después por CLI tendrá otro hash temporal, con los mismos casos.

Pendiente para un circuito completo: registro y custodia de candidatos congelados, ejecución independiente autorizada, holdout nuevo con anotación humana ciega, comparación de candidatos, decisión humana de promoción y rollback. Esta fase no implementa ni promete automejora, entrenamiento, promoción o despliegue de modelos. La UI y API no ofrecen esa acción y reportan `promotionEnabled:false`.
