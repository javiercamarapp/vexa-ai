Los resultados individuales permanecen en push_attempts. Los dispositivos rechazados no se convierten en delivered.

## UI, sesión y PWA

`GET /api/notifications/push`: dispositivos saneados de usuario/scope, observedAt, configuración pública y deviceId actual. `POST` registra `{op:'register',consent:true,subscription}` o revoca `{op:'revoke',id}`; origen verificado, límite8192 bytes y deadline total5s con cancelación de lectura;400 para JSON/UTF8 inválido,413 para exceso y408 para timeout, cookie opaca HttpOnly/SameSite Strict, sin claves/tenant/usuario recibidos como autorización. UI `/notifications/push` pide permiso sólo por botón explícito. Preferencias por evento permanecen separadas de permiso del navegador. Registro no anuncia entrega.

`/service-worker.js` no cachea páginas ni identidad. El transporte incluye sólo texto/CTA fijos y los correladores opacos subscriptionId/version del registro autorizado por SQL. El SW ignora texto/CTA entrantes y exige que los dos correladores coincidan con el dispositivo actual activo obtenido de la API; descarta mensajes de registros anteriores, aunque un dispositivo se reactive. No hay usuario, tenant ni datos de negocio en el payload. Click siempre abre `/notifications` del mismo origin con autorización normal vigente. Rotación del navegador exige nueva activación explícita. Manifest propio sólo enlazado desde página Push, scope `/`, sin cambios de layout global. En Safari/iOS siguen pendientes ensayos en dispositivo real autorizado.

Cambio de organización revoca este dispositivo antes de modificar selector, usando la organización nueva ya autorizada como scope para no depender de una membresía anterior revocada. Logout conserva `signOut({scope:'global'})` sin exigir workspace: Auth elimina las sesiones y la FK SET NULL con trigger revoca los dispositivos conservando los intentos históricos. Limpia también vexa_push_device; devuelve503 si Auth no confirma la revocación. Funciona igualmente para administración de plataforma sin membresía. El remitente vuelve a comprobar auth.sessions; no usa únicamente la cookie cliente. Un efecto iniciado justo antes de una revocación no se puede retirar; por eso el contenido es genérico y SW/CTA revalidan acceso. No se afirma serialización de una transacción SQL con Internet.
